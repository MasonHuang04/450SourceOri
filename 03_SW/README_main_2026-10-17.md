# Main 上位机：短窗采集、FFT与FPGA插值（2026-10-20）

双击`RunMain.cmd`启动Release程序。请先下载配套的短窗Main `02_RTL/V0/output_files/UsMimoTestBench.sof`。本次更新同时涉及FPGA与上位机，旧长窗固件不能直接套用短窗设置。

## 使用

1. 主板USB-C接电脑并供电、S1打开。关闭其他占用同一COM口的程序。
2. 刷新COM列表并连接。保持TX默认40 kHz中心、4 kHz带宽、20 ms、幅度0.25。
3. 用外部发生器连续100 Hz小幅正弦接P5 RX_IN，并共地。RX参考频率填100；它只用于误差评价。
4. 点击“应用并采集一次”，检查约5442点时域波形、原频点与插值频率。连接本身不触发；“仅应用TX参数”也不触发。
5. 可改发生器频率并更新参考值后再次采集，无需重编译。当前短窗下25 Hz不可靠。

## 固定的Main短窗配置

RX延迟1 ms，采集19 ms；原始ADC约1.145833 MS/s，原始回传每4点留1点。FFT分支独立CIC /32，35.807292 kS/s，672有效点（18.767 ms），补零到1024点。名义搜索25–500 Hz，频率格34.968058 Hz。

峰值插值在FPGA内完成。上位机根据M3报文中的FFT长度、峰值bin与Q16偏移换算Hz，不再固定按8192点换算。即使插值计算正确，短窗也可能使低频估计产生很大偏差；不足3个估计周期时显示橙色“短窗低频，仅供参考”。

TX仍由上位机原64字节设置协议调整中心频率、带宽、时长和幅度。每个设置包会同时带上RX19 ms配置。TX时长变化不会自动改变RX窗口，当前窗口只按默认20 ms Chirp安排。TX输入限制仍为时长0.01–100 ms、幅度0–1、扫频范围大于0且不超过1 MHz；这不是对模拟电路/换能器全频段能力的承诺。

## 显示、保存与兼容性

- 波形横轴从本帧第一个回传点开始，不是传播时间；纵轴是ADC数字码减32768，未标定为伏特。
- 原频点与插值频率同时显示；数据削顶、空/短窗口、节拍错误等仍会标为无效。
- 功率是原最大频点功率，单位归一化ADC code²，不是声功率。
- CSV记录原频点、插值结果、FFT长度、有效点数、插值状态以及短窗提示。日志在Release程序旁的DataSessions。
- 波形支持缩放/拖动及完整CSV导出；未回传完整频谱，所以界面不显示虚构频谱。
- “离线演示”使用合成100 Hz波形和示例结果，不连接板子。连续模式仍等待当前帧全部结束后再间隔约1秒触发。
- 解析器兼容历史M1/M2和当前M3。实板短窗测试必须使用本次固件；旧GUI不能识别M3，且旧固件无法在19 ms内采满8192个FFT有效点。

## 配置和构建

主配置在`02_RTL/V0/Simulation/FFT/main_settings.json`。`configure_main.py`会同时更新RTL/ROM和MainProtocol.cs里的BEGIN_MAIN_PROFILE块；重新编译FPGA与上位机后生效。GUI当前文字说明针对默认短窗配置；自定义其他窗口时需同步检查展示和测试预期。

使用.NET Framework 4.8与原`UsMimoTestBench.sln`。`Build.ps1`可重建Release/Debug；当前已发布并验证Release。软件没有JTAG烧录功能。
